# In-app updates

FuelNote and Discipline share one updater. Open **App updates** from FuelNote Profile
or the bottom of Discipline. Version 0.9.1 introduces this feature;
older installations need this APK installed once using the existing download link.

The default automatic check runs when any section is opened, at most once per six
hours after a successful check. Failed checks wait at least 15 minutes before another
automatic attempt. The update screen can check immediately and disable automatic
checks. No background polling, account, token or nutrition data is required.

**Download update** downloads the APK directly from the public GitHub release with
progress and cancellation. Navigating elsewhere in the app does not cancel it. A
completed verified download survives app restarts while Android retains the app
cache. An interrupted download is retried from the beginning; it does not claim to
resume partial bytes or survive Android terminating the process.

**Install update** verifies the bytes and package again, requests Android's permission
to install from this app if needed, and opens Android's installer. After enabling the
permission, return and tap Install update again. Android always owns the installation
confirmation. Cancelling installation retains the download for another attempt.
The package and signing identity must match the current installation; updates preserve
its app data. A differently signed development build is deliberately rejected.

## Release contract

The source endpoint is the repository's `dietlog-latest` release, not GitHub's generic
latest endpoint (this repository contains multiple Android apps). It must contain:

- `DietLog-debug.apk`, the existing stable CI signed debug distribution.
- `dietlog-update.json`, generated by `tools/build_update_manifest.py` from that exact
  final APK. Schema 1 contains `versionCode`, `versionName`, `packageName`, `apkName`,
  `apkSha256`, and `apkSize`.

The workflow uploads both assets after tests, lint, build and signing verification.
Metadata must match GitHub's asset sizes and SHA-256 digests when available. Asset ID
cache keys distinguish replacements of the rolling download URLs. Temporary mismatch
while publishing a release fails closed; a later check can retry.

The client permits only HTTPS on the named GitHub API/download hosts, bounds redirects,
response sizes and request times, writes only to its private `cache/updates/`, and
atomically promotes verified downloads. Before installation it checks the SHA-256,
size, package ID, newer version code, version name, minimum Android SDK, and exact
current signing certificate set. The FileProvider exposes only this update directory
through temporary read grants. No storage permission is requested.

Update diagnostics record action outcomes and exception types, never API bodies,
redirect query strings, credentials or personal app data.
